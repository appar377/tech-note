ブランチを切り替えるなら`git switch`、ファイルの内容を戻すなら`git restore`と分けると、操作の対象が読み取りやすくなります。`git checkout`も使えますが、引数によってブランチ切り替えにもファイル復元にもなるため、コマンド名だけでは判断できません。

ただし、`switch`なら未コミットの変更を必ず残せる、`restore`なら最後のコミットへ戻る、と覚えるのも不正確です。切り替えが拒否される条件と、復元元・復元先を分けて確認します。

## どの操作をしたいのか

| 目的 | 操作例 | 注目する点 |
| --- | --- | --- |
| 既存ブランチへ移る | `git switch topic` | HEADが参照するブランチを変えます |
| 現在地から新しいブランチを作る | `git switch -c topic` | ブランチ名を作って切り替えます |
| ブランチを動かさずコミットを見る | `git switch --detach HEAD` | HEADがコミットを直接指します |
| ステージしていない編集を戻す | `git restore -- note.txt` | 通常はindexの内容を作業ファイルへ戻します |
| ステージを外す | `git restore --staged -- note.txt` | 通常はHEADの内容をindexへ戻します |

`switch`と`restore`はGit 2.23で登場したコマンドです。従来の`checkout topic`はブランチ切り替え、`checkout topic -- note.txt`はファイル復元に当たります。[git-switch](https://git-scm.com/docs/git-switch/2.30.0)、[git-checkout](https://git-scm.com/docs/git-checkout)にそれぞれの形式が説明されています。

ここで、HEADは現在地を示す参照、indexは次のコミットへ入れる内容、working treeは実際に編集するファイルです。ブランチ切り替えではこれらが関係しますが、未コミットの変更があるときにindexとworking treeを無条件で切り替え先へ上書きするわけではありません。

## 未コミットの編集があると、切り替えられないのか

以下は説明用のファイルだけを扱う再現例です。Git 2.46.0とmacOSの `/bin/bash` で実行し、記載した状態を確認しました。再現コードはGit 2.34以上を前提にしますが、その全バージョンで動作を確認したものではありません。

この記事の`bash`ブロックを上から順に一つの`example.sh`へ保存し、`/bin/bash example.sh`で実行する構成です。端末へ断片だけ貼り付けたり、`source`で読み込んだりしないでください。最初に環境を分け、新しい一時ディレクトリ内にリポジトリを作ります。既存のGit設定を変更せず、このリポジトリにだけ説明用の名前・メールアドレスと署名無効を設定します。remoteは作らず、通信もしません。

`expect_status`は終了コードが期待どおりか調べる関数です。`test`が失敗するとスクリプトはそこで止まります。出力の`REPO`が再現用リポジトリの場所です。

```bash file=setup.sh
set -eu

# Save all blocks as one file and run it with /bin/bash, not by sourcing it.
if [ "${1:-}" != "--isolated" ]; then
  exec env -i PATH="$PATH" TMPDIR="${TMPDIR:-/tmp}" LC_ALL=C \
    GIT_CONFIG_NOSYSTEM=1 GIT_CONFIG_SYSTEM=/dev/null \
    GIT_CONFIG_GLOBAL=/dev/null GIT_ATTR_NOSYSTEM=1 \
    GIT_TERMINAL_PROMPT=0 GIT_EDITOR=true GIT_SEQUENCE_EDITOR=true \
    /bin/bash "$0" --isolated
fi

demo_root=$(mktemp -d "${TMPDIR%/}/git-note.XXXXXX")
mkdir "$demo_root/repo" "$demo_root/empty-template" "$demo_root/empty-hooks"
cd "$demo_root/repo"
git --version
git init -q -b main --template="$demo_root/empty-template"
git config --local user.name 'Git Example'
git config --local user.email 'git-example@example.invalid'
git config --local commit.gpgSign false
git config --local tag.gpgSign false
git config --local core.hooksPath "$demo_root/empty-hooks"
git config --local core.autocrlf false
git config --local gc.auto 0
git config --local maintenance.auto false
git config --local rerere.enabled false
printf 'REPO %s\n' "$demo_root/repo"

expect_status() {
  expected_status=$1
  shift
  if "$@"; then actual_status=0; else actual_status=$?; fi
  if [ "$actual_status" -ne "$expected_status" ]; then
    printf 'Expected status %s, got %s\n' "$expected_status" "$actual_status" >&2
    exit 1
  fi
}
```

まず、`main`と`topic`で`note.txt`の内容だけを変えます。両ブランチで同じ`shared.txt`への編集は持ち越せます。一方、`main`で編集した`note.txt`は切り替え先にも別の内容があるため、この例では切り替えが拒否されます。

```bash file=switch-checkout/01-branches.sh
printf 'base\n' > note.txt
printf 'shared\n' > shared.txt
git add note.txt shared.txt
git commit -qm 'Base'
git switch -c topic
printf 'topic\n' > note.txt
git commit -qam 'Change note on topic'
git switch main

printf 'local draft\n' > shared.txt
git switch topic
test "$(git branch --show-current)" = topic
test "$(cat shared.txt)" = 'local draft'
test "$(git show :shared.txt)" = shared
git checkout main
test "$(git branch --show-current)" = main
test "$(cat shared.txt)" = 'local draft'
printf 'CHECK unrelated_edit=preserved_by_switch_and_checkout\n'

# Discard only the explanation's dummy edit before the next case.
git restore -- shared.txt
printf 'local note\n' > note.txt
expect_status 1 git switch topic
test "$(git branch --show-current)" = main
test "$(cat note.txt)" = 'local note'
test "$(git show :note.txt)" = base
printf 'CHECK overlapping_edit=refused_and_preserved\n'
git restore -- note.txt
```

前半の期待値は、切り替え後も作業ファイルに`local draft`が残り、indexの内容は`shared`のままであることです。`switch`だけでなく、ブランチ切り替えとしての`checkout`も確認しています。

後半は、`git switch topic`が終了コード1で止まり、現在のブランチが`main`、作業ファイルが`local note`のままであることを調べます。「未コミットだからすべて拒否」でも「切り替え先へ編集が必ず引き継がれる」でもありません。通常の切り替えではローカルの変更を失う操作を拒否する、と[公式の説明](https://git-scm.com/docs/git-switch/2.30.0#_description)から判断できます。

実作業で拒否されたら、`git status`、`git diff`、`git diff --cached`で変更先を確認し、コミットするか一時退避するかを選びます。`--discard-changes`は編集を捨てる指定なので、切り替えエラーを消すためだけに付けないようにします。例中の`restore`は説明用の編集を意図的に捨てる操作です。

## restoreは何をどこへ戻すのか

`note.txt`のHEADを`base`、indexを`staged`、working treeを`unstaged`にして、復元先を見ます。[git-restore](https://git-scm.com/docs/git-restore/2.30.0)では、指定を省いた場合の復元元はindex、`--staged`を付けた場合はHEADと定義されています。

```bash file=switch-checkout/02-restore.sh
printf 'staged\n' > note.txt
git add note.txt
printf 'unstaged\n' > note.txt
git restore -- note.txt
test "$(cat note.txt)" = staged
test "$(git show :note.txt)" = staged
test "$(git show HEAD:note.txt)" = base
printf 'CHECK restore_default=index_to_worktree\n'

git restore --staged -- note.txt
test "$(git show :note.txt)" = base
test "$(cat note.txt)" = staged
printf 'CHECK restore_staged=head_to_index_only\n'

git restore --source=topic -- note.txt
test "$(cat note.txt)" = topic
test "$(git show :note.txt)" = base
printf 'CHECK restore_source=worktree_only\n'

git checkout topic -- note.txt
test "$(cat note.txt)" = topic
test "$(git show :note.txt)" = topic
test "$(git branch --show-current)" = main
printf 'CHECK checkout_path=index_and_worktree_branch_unchanged\n'

git restore --source=HEAD --staged --worktree -- note.txt
test -z "$(git status --porcelain)"
```

この例で確認する状態は次のとおりです。すべての行でHEADは`main`を参照し続けます。

| 実行した操作 | indexのnote.txt | working treeのnote.txt |
| --- | --- | --- |
| `git restore -- note.txt` | staged | staged |
| `git restore --staged -- note.txt` | base | staged |
| `git restore --source=topic -- note.txt` | base | topic |
| `git checkout topic -- note.txt` | topic | topic |

特に最後の2つは同じではありません。`checkout topic -- note.txt`は指定した内容をindexにも入れます。これに対応させるなら、復元元にそのファイルが存在するこの例では`git restore --source=topic --staged --worktree -- note.txt`です。[checkoutのパス指定](https://git-scm.com/docs/git-checkout#_description)を読む際は、ブランチを移動したと思い込まず、ステージの変化も確認します。

なお、復元元にないファイルの扱いまで両者が常に同じとは限りません。`restore`は復元元に合わせて追跡ファイルを削除する一方、`checkout`のパス復元は既定でoverlay動作です。上の対応は、双方に存在する`note.txt`に限定しています。

## detached HEADでの確認をブランチに残すには

ブランチを進めずにあるコミットを確認したい場合は、`--detach`を使います。HEADがブランチ名を経由せずコミットを指す状態です。そこでの作業を残すなら、別の場所へ移る前にブランチ名を付けられます。[detached HEADの説明](https://git-scm.com/docs/git-checkout#_detached_head)を参照してください。

```bash file=switch-checkout/03-detach.sh
git switch --detach HEAD
expect_status 1 git symbolic-ref -q HEAD
test "$(git rev-parse HEAD)" = "$(git rev-parse main)"
git switch -c inspection
test "$(git branch --show-current)" = inspection
test "$(git rev-parse inspection)" = "$(git rev-parse main)"
printf 'CHECK detached_head=new_branch_can_name_current_commit\n'
```

この例では新しいコミットを作らず、同じコミットへ`inspection`というブランチ名を付けます。`switch`は移動先、`restore`は復元元と復元先、`checkout`はどちらの形式なのかを読むと、操作後の状態を予測しやすくなります。

履歴を取り込む操作との違いは、[PRのマージ方式](/tech-note/articles/github/pull-request/merge-methods/)で扱います。
