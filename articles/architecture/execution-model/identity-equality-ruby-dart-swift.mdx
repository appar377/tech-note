同じSKUの商品を2つのオブジェクトに読み込み、Setへ入れたら2件になった。「同じ商品」と「同じインスタンス」が別の判断なら、それはコレクションの契約に沿った結果かもしれません。

この記事では、商品を `catalog` と `sku` の組で区別する説明用の値を使います。Ruby 3.4.4、Dart 3.11.5、Apple Swift 6.3.3のCLI向けに用意した例です。各言語のファイルを独立して実行し、出力を期待値と照合しました。Swiftは言語モード6、macOS SDK26.5、target `arm64-apple-macosx26.0`で確認しています。hashの数値やメモリアドレスは期待値にしません。

## Rubyでは、==がtrueでもHashの同じキーとは限りませんか？

Rubyの `equal?` は同一オブジェクトかを調べます。`==` は型に応じた等価性として再定義できます。一方、通常のHashが同じキーと扱うには、`eql?` と `hash` の契約を満たす必要があります。例えば `1 == 1.0` はtrueでも、`1.eql?(1.0)` はfalseです。[Ruby 3.4: BasicObject](https://docs.ruby-lang.org/en/3.4/BasicObject.html#method-i-equal-3F)、[Hash key equivalence](https://docs.ruby-lang.org/en/3.4/Hash.html#class-Hash-label-Hash+Key+Equivalence)

商品キーには `Data` を使い、2つの文字列を組み合わせた値として比較します。保持する文字列も複製してfreezeし、呼び出し側による後からの変更を切り離しています。

```ruby file="identity.rb"
require "json"

ProductKey = Data.define(:catalog, :sku) do
  def initialize(catalog:, sku:)
    super(catalog: catalog.dup.freeze, sku: sku.dup.freeze)
  end
end

first = ProductKey.new(catalog: "jp", sku: "sku-1")
second = ProductKey.new(catalog: "jp", sku: "sku-1")
same_reference = first
stock = { first => 12 }
source_sku = +"sku-1"
copied_key = ProductKey.new(catalog: "jp", sku: source_sku)
source_sku.replace("sku-2")

puts JSON.generate({
  identity_and_value: {
    same_object: first.equal?(second),
    same_value: first == second,
    same_key: first.eql?(second),
    alias_identity: first.equal?(same_reference)
  },
  hash_contract: {
    equal_hash: first.hash == second.hash,
    lookup: stock[second],
    distinct_keys: [first, second].to_h { |key| [key, 12] }.size,
    other_catalog: first == ProductKey.new(catalog: "eu", sku: "sku-1")
  },
  copied_input: { sku: copied_key.sku, lookup: stock[copied_key] },
  numeric_keys: { same_value: 1 == 1.0, same_key: 1.eql?(1.0), count: { 1 => "int", 1.0 => "float" }.size }
})
```

`first` と `second` は別オブジェクトですが、同じ値・同じHashキーとして扱われます。期待値は `same_object: false`、`same_value: true`、`same_key: true`、`lookup: 12` です。一方 `same_reference` は `first` と同じオブジェクトなので、`alias_identity` はtrueになります。

`Data` 自体に属性のwriterがないことと、内部のオブジェクトが変更できないことは別です。配列などの可変値を格納しても、自動で深くfreezeされるわけではありません。上の複製とfreezeは、この商品キーがStringを受け取るという前提のための処理です。[Ruby 3.4: Data](https://docs.ruby-lang.org/en/3.4/Data.html)

## Dartでは、フィールドが同じなら==もtrueになりますか？

通常の自作クラスが継承する `Object.==` は同一性に基づきます。`ProductReference` のSKUが同じでも、別インスタンスなら既定の比較はfalseです。値で比較したい `ProductKey` では、`==` と `hashCode` を一緒に定義します。[Dart 3.11.5: Objectの契約](https://github.com/dart-lang/sdk/blob/3.11.5/sdk/lib/core/object.dart)

```dart file="identity.dart"
import 'dart:collection';
import 'dart:convert';

final class ProductReference {
  final String sku;
  ProductReference(this.sku);
}

final class ProductKey {
  final String catalog;
  final String sku;
  ProductKey(this.catalog, this.sku);

  @override
  bool operator ==(Object other) =>
      other is ProductKey && catalog == other.catalog && sku == other.sku;

  @override
  int get hashCode => Object.hash(catalog, sku);
}

void main() {
  final rawFirst = ProductReference('sku-1');
  final rawSecond = ProductReference('sku-1');
  final first = ProductKey('jp', 'sku-1');
  final second = ProductKey('jp', 'sku-1');
  final sameReference = first;
  final keys = HashSet<ProductKey>()..addAll([first, second]);
  final identities = HashSet<ProductKey>.identity()..addAll([first, second]);
  final stock = <ProductKey, int>{first: 12};

  print(jsonEncode({
    'default_comparison': {
      'same_value': rawFirst == rawSecond,
      'set_size': (HashSet<ProductReference>()..addAll([rawFirst, rawSecond])).length,
    },
    'identity_and_value': {
      'same_object': identical(first, second),
      'same_value': first == second,
      'alias_identity': identical(first, sameReference),
    },
    'hash_contract': {
      'equal_hash': first.hashCode == second.hashCode,
      'lookup': stock[second],
      'distinct_keys': keys.length,
      'other_catalog': first == ProductKey('eu', 'sku-1'),
    },
    'identity_set_size': identities.length,
  }));
}
```

`default_comparison.set_size` は2、`hash_contract.distinct_keys` は1が期待値です。比較の基準を変えたことで、同じ商品キーが集合の1要素になります。カタログが違う場合はSKUが同じでも別のキーとするため、`other_catalog` はfalseです。

同一性で区別することが目的なら、`HashSet.identity()` を使う選択もあります。この例の `identity_set_size` は2になります。「常に値比較へ変える」のではなく、その集合が何を区別するのかを決めます。[Dart 3.11.5: HashSet](https://github.com/dart-lang/sdk/blob/3.11.5/sdk/lib/collection/hash_set.dart)

ここではconstではない通常のコンストラクターで2つのインスタンスを作っています。constの正規化や数値・recordの同一性まで、この結果から一般化しません。Dart単体の詳細は[identical・等価性・hashCode](/tech-note/articles/flutter/dart/dart-identity-equality-hashcode-equatable/)で扱います。

## Swiftの===は、structにも使うのですか？

Swiftの `===` はclassインスタンスの同一性を調べます。structは値型なので、同じ演算子で参照を比較する対象にはしません。`==` は `Equatable` の契約です。[The Swift Programming Language: Structures and Classes](https://docs.swift.org/swift-book/documentation/the-swift-programming-language/classesandstructures/)

次は商品キーをstructで、同じ商品キーを持つ参照オブジェクトをclassで表した例です。`identity.swift` をSwift 6言語モードで実行しました。Foundationは結果をJSONにするためだけに使用し、SwiftUIやactorは使いません。

```swift file="identity.swift"
import Foundation

struct ProductKey: Hashable {
    let catalog: String
    let sku: String
}

final class ProductReference: Equatable {
    let key: ProductKey
    init(key: ProductKey) { self.key = key }

    static func == (lhs: ProductReference, rhs: ProductReference) -> Bool {
        lhs.key == rhs.key
    }
}

let firstKey = ProductKey(catalog: "jp", sku: "sku-1")
let secondKey = ProductKey(catalog: "jp", sku: "sku-1")
let first = ProductReference(key: firstKey)
let second = ProductReference(key: secondKey)
let sameReference = first
let stock = [firstKey: 12]

let result: [String: Any] = [
    "identity_and_value": [
        "same_object": first === second,
        "same_value": first == second,
        "alias_identity": first === sameReference
    ],
    "hash_contract": [
        "equal_hash": firstKey.hashValue == secondKey.hashValue,
        "lookup": stock[secondKey]!,
        "distinct_keys": Set([firstKey, secondKey]).count,
        "other_catalog": firstKey == ProductKey(catalog: "eu", sku: "sku-1")
    ] as [String: Any]
]
let data = try JSONSerialization.data(withJSONObject: result, options: [.sortedKeys])
print(String(decoding: data, as: UTF8.self))
```

`first === second` はfalseでも、ここで定義した `first == second` はtrueになります。classにも値に基づく等価性を定義できるためです。

`ProductKey` は全ての保存プロパティが `Hashable` なので、`==` と `hash(into:)` の合成を利用できます。Setの要素数は1、別に作ったキーでDictionaryから取得する値は12が期待値です。[Swift 6.3.3: Hashable](https://github.com/swiftlang/swift/blob/swift-6.3.3-RELEASE/stdlib/public/core/Hashable.swift)

## hashが同じなら、同じ値だと判断できますか？

必要なのは「等しいと扱う値には同じhashを与える」という方向の契約です。逆方向は保証されず、異なる値でもhashが衝突することがあります。hashだけを永続IDや等価性の判定に使わないでください。DartやSwiftでは、別の実行で同じhash値が得られる保証もありません。[Dart 3.11.5: hashCode](https://github.com/dart-lang/sdk/blob/3.11.5/sdk/lib/core/object.dart)、[Swift 6.3.3: Hashable](https://github.com/swiftlang/swift/blob/swift-6.3.3-RELEASE/stdlib/public/core/Hashable.swift)

また、キーとして格納している間に比較やhashへ使う内容を変えると、コレクションの前提が崩れます。上の例では不変の文字列からキーを作っています。Rubyの通常のHashには、Stringキーを複製してfreezeする仕組みがありますが、自作の複合キーの内部まで同じ保護が行われるわけではありません。[Ruby 3.4: Modifying an Active Hash Key](https://docs.ruby-lang.org/en/3.4/Hash.html#class-Hash-label-Modifying+an+Active+Hash+Key)

## DBのIDやUIのidentityも、同じ話ですか？

何を同じものとして追跡するかは共通の問いですが、判定の契約は別です。

Active Record 8.1.3の `==` は、同じRubyオブジェクトか、同じモデルクラスでprimary keyが存在し一致するかを判定します。全属性の一致を判定しているわけではありません。同じ行を別インスタンスとして読み込んだ場合、`==` がtrueでも `equal?` はfalseになり得ます。この節は公式実装による確認で、今回のCLI例ではDBの読み込みは実行しません。[Rails 8.1.3: ActiveRecord::Core#==](https://api.rubyonrails.org/v8.1.3/classes/ActiveRecord/Core.html#method-i-3D-3D)

そのため、変更検知で「内容が変わったか」を調べたいのに、Entityの `==` をそのまま使うと目的がずれます。DBの識別、メモリ上の共有、属性の比較を別々にします。[Active Recordの保存差分とインスタンスの寿命](/tech-note/articles/rails/active_record/active-record-dirty-tracking-lifecycle/)もこの区別が前提です。

UIにも個別の契約があります。例えばFlutterの `Widget.canUpdate` は、旧Widgetと新Widgetの `runtimeType` と `key` の一致を使います。モデルの全フィールドの等価性とは違う判断です。[Flutter: Widget.canUpdate](https://api.flutter.dev/flutter/widgets/Widget/canUpdate.html)

Swiftの `Identifiable` もidentityの有効期間や範囲を一律には決めません。class向け既定実装はオブジェクトの寿命に基づくため、DBの永続IDが必要なら、その契約を自分で与えます。ここではUIの再描画や状態保持を検証したとは扱いません。[Swift 6.3.3: Identifiableの契約](https://github.com/swiftlang/swift/blob/swift-6.3.3-RELEASE/stdlib/public/core/Identifiable.swift)

比較を書く前に、「同じインスタンスを共有しているか」「同じ商品キーか」「同じ保存先の行か」「同じUI要素として追跡するか」を言葉にします。その答えに合わせて、演算子、値型、キーの構成を選べます。
