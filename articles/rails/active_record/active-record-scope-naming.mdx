`highest_price_first` という名前は、「価格の高い順に並んだ集合」とも「最高価格の商品1件」とも読めます。名前だけを直す前に、呼び出し元が絞り込みや件数指定を続けられるのか、すでに1件を取り出しているのかを分けます。

並べ替えはRelationを返すscopeにし、1件を取り出す処理はmodelまたは `nil` を返すメソッドにすると、戻り値を予測しやすくなります。特定の英語名を正解にするのではなく、この二つの契約を一つの名前へ混ぜないことが目的です。

以下は説明用の商品モデルです。Ruby 3.4.4、Active Record 8.1.3、PostgreSQL 17.10で確認しました。`scoped_products` の `name:string`、`price:integer`、`active:boolean`、`created_at:datetime` はすべてNULL不可とします。価格は単位を統一した整数で、小数や通貨の変換は扱いません。

## 集合と1件を、別のAPIにする

```ruby
class ScopedProduct < ActiveRecord::Base
  scope :active, -> { where(active: true) }
  scope :price_desc, -> { order(price: :desc, created_at: :desc, id: :desc) }
  scope :highest_price_first, -> { price_desc }

  def self.highest_priced
    price_desc.first
  end
end
```

`price_desc` は並び順を追加するscopeです。旧名の `highest_price_first` は呼び出し元を移行する間の互換用として残しました。`highest_priced` は、そのRelationから1件を取り出します。

| 呼び出し | この実装の戻り値 | 対象がない場合 |
| --- | --- | --- |
| `ScopedProduct.price_desc` | Relation | 空のRelation |
| `ScopedProduct.price_desc.limit(1)` | 最大1件のRelation | 空のRelation |
| `ScopedProduct.highest_priced` | ScopedProduct | `nil` |

[scopeの公式API](https://api.rubyonrails.org/v8.1.3/classes/ActiveRecord/Scoping/Named/ClassMethods.html#method-i-scope)は、他のscopeと組み合わせられるRelationを返す意図のメソッドと説明しています。`limit(1)` は型を1件のmodelへ変えません。`first` は結果を取り出す操作です。

`expensive_first` を集合の順序として使う規約も成立します。`first` という単語を一律に禁止する必要はありません。短い名前を選ぶ場合も、1件を返す名前との対応を揃えます。

## 同じ価格の商品を、何で並べるか

説明用に同額・同時刻の行を含むデータを作ります。

```ruby
a = ScopedProduct.create!(name: 'A', price: 10, active: true, created_at: Time.utc(2026, 1, 1))
b = ScopedProduct.create!(name: 'B', price: 30, active: true, created_at: Time.utc(2026, 1, 1))
c = ScopedProduct.create!(name: 'C', price: 30, active: true, created_at: Time.utc(2026, 1, 2))
d = ScopedProduct.create!(name: 'D', price: 30, active: true, created_at: Time.utc(2026, 1, 2))
ScopedProduct.create!(name: 'E', price: 99, active: false, created_at: Time.utc(2026, 1, 2))

ScopedProduct.active.price_desc.pluck(:name) # => ['D', 'C', 'B', 'A']
```

価格が同じなら作成日時を降順にし、それも同じなら一意な `id` の降順にします。ここではDをCの後に作ったため、DのIDが大きくなります。IDが常に実世界の発生順を表すという意味ではありません。

[PostgreSQLのORDER BY](https://www.postgresql.org/docs/17/queries-order.html)では、先の式が同値の場合に次の式を使います。`price` だけで並べたときの同額行の順序へ依存しないようにします。この例はNULLを許さない前提です。NULLを許す設計では、NULLを先頭と末尾のどちらへ置くかも決めます。

一意なtie-breakerは、同じデータ集合の順序を決めるためのものです。ページをめくる間の追加・削除によって集合が変わる問題まで解決するわけではありません。

## 絞り込みと件数指定を続けられるか確認する

```ruby
relation = ScopedProduct.active.price_desc
relation.is_a?(ActiveRecord::Relation) # => true
!!relation.loaded? # => false
relation.limit(2).pluck(:name) # => ['D', 'C']
ScopedProduct.active.highest_priced.name # => 'D'
ScopedProduct.where(name: 'missing').highest_priced # => nil
```

Relationを作った時点では、まだ行を読み込んでいません。この例では `pluck` や `first` で結果を取り出します。[Relationの遅延読込と検索の説明](https://guides.rubyonrails.org/active_record_querying.html#understanding-the-method-chaining)にも対応する使い方が示されています。

命名を変えた後のテストは、名前が呼べることだけでなく、Relationを返すこと、同額時の順序、空集合、絞り込みとの合成を対象にします。旧名を残す間は次の比較もできます。

```ruby
ScopedProduct.highest_price_first.ids == ScopedProduct.price_desc.ids # => true
```

旧名の利用箇所を検索し、関連経由の呼び出しや公開APIも確認してから取り除きます。この別名は移行用であり、同じ責務の名前を恒久的に増やすためのものではありません。

## orderは、既存の並び順を消さない

```ruby
by_name = ScopedProduct.active.order(name: :asc)
by_name.price_desc.pluck(:name) # => ['A', 'B', 'C', 'D']
by_name.reorder(price: :desc, created_at: :desc, id: :desc).pluck(:name)
# => ['D', 'C', 'B', 'A']
```

`order` は既存の順序へ追加するため、最初の名前順が優先されます。`reorder` は既存の順序を置き換えます。[QueryMethodsのreorder](https://api.rubyonrails.org/v8.1.3/classes/ActiveRecord/QueryMethods.html#method-i-reorder)がこの違いを説明しています。

scope内で `order` と `reorder` のどちらを使うかは、そのscopeが呼び出し元の順序を尊重するか、置き換えるかという契約です。「常に価格を最優先にする」と説明しながら `order` を追加するだけにしないよう、名前と呼び出し方の両方を確認します。

## scopeの中でfirstすると、空のときの戻り値が変わる

最後は避けたい例です。戻り値の違いを調べるため、同じテーブルへ別モデルを割り当てます。

```ruby
class BrokenScopeProduct < ActiveRecord::Base
  self.table_name = 'scoped_products'
  scope :one_product, -> { order(price: :desc, id: :desc).first }
end

BrokenScopeProduct.one_product.is_a?(BrokenScopeProduct) # => true
BrokenScopeProduct.none.one_product.is_a?(ActiveRecord::Relation) # => true
BrokenScopeProduct.none.one_product.to_a # => []
```

この版のscopeは、blockが `nil` や `false` を返すとRelationへフォールバックします。対象があればmodel、なければ空のRelationという不揃いな戻り値になります。scope宣言だけで戻り値の型が強制される、と解釈してはいけません。[公式APIのnil/false時の仕様](https://api.rubyonrails.org/v8.1.3/classes/ActiveRecord/Scoping/Named/ClassMethods.html#method-i-scope)と実行結果が根拠です。

1件を返したい処理は `highest_priced` のような通常のクラスメソッドに置けば、空のときに `nil` を返す契約を保てます。ここでは戻り値・順序・合成・互換名・orderの追加・nil時の挙動を8例で確認しました。命名による開発速度やDB性能の改善は測定していません。
