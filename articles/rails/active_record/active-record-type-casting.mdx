## 概要

HTTPパラメータは文字列なのに、モデルへ代入すると整数や日付として扱える。`type_for_attribute(:price).cast`を見たことで、型変換がどの層で起きるかを理解する必要が出てきた。

Active Recordの型システムは、ユーザー入力をRuby値へ変換する`cast`、DB表現へ変換する`serialize`、DB値をRubyへ戻す`deserialize`を分けて扱う。

## この記事で学べること

- HTTPパラメータが基本的に文字列であること
- モデル属性へ代入したときの型変換
- `type_for_attribute`が返すTypeオブジェクト
- `cast`、`serialize`、`deserialize`の責務
- 空文字、nil、真偽値、decimal、dateの例
- 浮動小数点を金額に使う危険性

## 前提知識

- Rails、Active Record、RSpec、SQLログの基本を読めること
- フレームワークのAPIを使った経験があり、状態・トランザクション・非同期処理の境界で詰まり始めていること
- この記事のコード例は匿名化した最小例であり、利用中のバージョンでは公式ドキュメントと実装を確認すること

## 実装コード例

```ruby
class Product < ApplicationRecord
  def self.cast_price(value)
    type_for_attribute("price").cast(value)
  end
end

Product.cast_price("1000")   #=> 1000
Product.cast_price("1000.5") #=> 1000
Product.cast_price(nil)      #=> nil

Product.new(price: "1000").price #=> 1000
```

## 内部動作

Railsの抽象化は、Rubyオブジェクト、Active Record、SQL、DBトランザクションの上に成り立っています。重要なのは、Railsのメソッド呼び出しがそのままDBの履歴や外部サービスの状態になるわけではない、という点です。

- 変換結果はカラム型・利用バージョン・アダプタで確認する
- `cast`は入力値の妥当性検証と同義ではない
- decimalはFloatではなくDecimal系型を意識する

```text
Ruby object
  -> Active Record
  -> SQL / transaction
  -> database row
  -> callback or job boundary
```
