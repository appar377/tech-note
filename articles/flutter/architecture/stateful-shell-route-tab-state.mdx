詳細画面を開いたまま別のタブへ移動し、戻ったときには同じ詳細画面を見せたい。この動作には、選択中のタブ番号だけでなく、タブごとのナビゲーション履歴が必要です。`StatefulShellRoute`では各branchに別のNavigatorを持たせ、その履歴を切り替えます。

説明用の例はFlutter 3.41.9、Dart SDK 3.11.5、go_router 17.3.0で確認しています。三つのタブに詳細ページとカウンターを置き、画面が保持される範囲を確かめます。

## 三つのタブに、三つのNavigatorを割り当てる

通常の`ShellRoute`が子ルートを一つのNavigatorに載せるのに対し、`StatefulShellRoute`はbranchごとにNavigatorを作ります。画面の外枠には`StatefulNavigationShell`を置き、タブ操作を`goBranch`へ渡します。[StatefulShellRouteの公式説明](https://pub.dev/documentation/go_router/latest/go_router/StatefulShellRoute-class.html)では、この違いを独立したナビゲーションツリーとして説明しています。

次の設定は`/home`、`/search`、`/settings`をbranchの入口にし、それぞれの下に`detail`を置きます。`GlobalKey`はbranchごとに新しく作り、別のNavigatorと共有しません。

```dart
import 'package:flutter/material.dart';
import 'package:go_router/go_router.dart';

const tabPaths = ['/home', '/search', '/settings'];
const tabLabels = ['ホーム', '検索', '設定'];

GoRouter createTabRouter({String initialLocation = '/home'}) {
  return GoRouter(
    initialLocation: initialLocation,
    routes: [
      StatefulShellRoute.indexedStack(
        builder: (context, state, shell) => Scaffold(
          body: shell,
          bottomNavigationBar: NavigationBar(
            selectedIndex: shell.currentIndex,
            onDestinationSelected: (index) => shell.goBranch(
              index,
              initialLocation: index == shell.currentIndex,
            ),
            destinations: [
              for (final label in tabLabels)
                NavigationDestination(
                  icon: const Icon(Icons.circle_outlined),
                  label: label,
                ),
            ],
          ),
        ),
        branches: [
          for (var i = 0; i < tabPaths.length; i++)
            StatefulShellBranch(
              navigatorKey: GlobalKey<NavigatorState>(),
              routes: [
                GoRoute(
                  path: tabPaths[i],
                  builder: (context, state) => TabCounterPage(
                    name: tabPaths[i],
                    detailLocation: '${tabPaths[i]}/detail',
                  ),
                  routes: [
                    GoRoute(
                      path: 'detail',
                      builder: (context, state) =>
                          TabCounterPage(name: '${tabPaths[i]}/detail'),
                    ),
                  ],
                ),
              ],
            ),
        ],
      ),
    ],
  );
}
```

`createTabRouter()`はアプリの組み立て時に一度呼び、そのGoRouterを`MaterialApp.router(routerConfig: router)`へ渡します。Widgetの`build`ごとに呼んでルーターを作り直すと、保持する対象も作り直すことになります。ルーターが不要になったら、その所有者が`router.dispose()`を呼びます。

`indexedStack`はbranchを並べて保持する標準のコンテナです。このコンテナ自体にはタブ間の切替アニメーションを追加していません。見た目のアニメーションを変える話と、Navigatorの履歴を分ける話は分けて扱えます。

## 保持されるのは、そのWidgetが持っているState

設定で使ったページは次の実装です。カウンターと`ScrollController`をStateに持たせ、詳細へ進む場合は入れ子のURLへ移動します。

```dart
class TabCounterPage extends StatefulWidget {
  const TabCounterPage({super.key, required this.name, this.detailLocation});
  final String name;
  final String? detailLocation;
  @override
  State<TabCounterPage> createState() => _TabCounterPageState();
}

class _TabCounterPageState extends State<TabCounterPage> {
  final _scroll = ScrollController();
  int _count = 0;
  @override
  void dispose() {
    _scroll.dispose();
    super.dispose();
  }

  @override
  Widget build(BuildContext context) => Scaffold(
    appBar: AppBar(title: Text(widget.name)),
    body: Column(
      children: [
        Text('count: $_count'),
        TextButton(
          onPressed: () => setState(() => _count++),
          child: const Text('増やす'),
        ),
        if (widget.detailLocation != null)
          TextButton(
            onPressed: () => context.go(widget.detailLocation!),
            child: const Text('詳細へ'),
          ),
        Expanded(
          child: ListView.builder(
            key: ValueKey('list:${widget.name}'),
            controller: _scroll,
            itemExtent: 48,
            itemCount: 50,
            itemBuilder: (context, index) => Text('項目 $index'),
          ),
        ),
      ],
    ),
  );
}
```

あるbranchの詳細でカウンターを増やし、別のタブへ移動して戻ると、その詳細ページとカウンターが残ります。branchの最初のページでリストをスクロールした場合も、同じ`ScrollController`が使われ、位置が保たれます。

これは画面が存続している間の状態です。サーバーのデータキャッシュや、アプリを終了した後の保存データを自動で作る機能ではありません。ルーターとWidgetツリーを破棄して作り直した検証では、カウンターは0へ戻りました。終了後の復元が必要なら、[FlutterのState restoration](https://docs.flutter.dev/platform-integration/android/restore-state-android)や業務データの永続化を別に設計します。

## 同じタブを押したときに、何を初期化するか

`goBranch`は通常、そのbranchで最後に表示していた場所へ戻ります。この例では、選択中のタブをもう一度押したときだけ`initialLocation: true`を渡し、branchの入口へ戻す方針です。[goBranchの仕様](https://pub.dev/documentation/go_router/latest/go_router/StatefulNavigationShell/goBranch.html)が、この引数による行き先の違いを定義しています。

入口へ戻ることと、WidgetのStateを消すことは同じではありません。検証では、入口のカウンターを1にして詳細へ進み、同じタブを再選択すると入口へ戻りますが、入口のカウンターは1のままでした。毎回0にする、リストの先頭へ戻す、といった動作は別のイベントとして実装します。

この例の操作の対応は次のとおりです。

| 操作 | この例での結果 |
| --- | --- |
| 別のタブを選ぶ | そのbranchの最後の場所へ移る |
| 選択中のタブを押す | そのbranchの入口へ戻る |
| 詳細で`router.pop()` | 同じbranchの入口へ戻る |
| branchの入口で`canPop()` | この構成では`false`になる |

branchの入口で戻れないときに「ホームのタブへ切り替える」といった要件は、この設定には含めていません。OSの戻る操作やブラウザの履歴を、タブを選んだ順番と同一視しないようにします。

## 深いURLと、画面を残す負担も確認する

初期URLを`/search/detail`にしたWidgetテストでは、検索タブが選ばれ、詳細ページが表示されます。そこから`pop`すると`/search`へ戻ります。これはルート設定に深いURLを与える検証で、OSからリンクを受け取る設定やブラウザの戻る・進むまで確認したものではありません。

一度表示したbranchを保持すると、そのWidgetやStateも残ります。go_router 17.3.0の[実装](https://github.com/flutter/packages/blob/go_router-v17.3.0/packages/go_router/lib/src/route.dart)では、非表示のbranchに`Offstage`と`TickerMode`を使っています。ただし、これを通信やTimerの自動終了と考えることはできません。画面が見えない間の処理を止める要件は、[通信のキャンセルと所有者の寿命](/tech-note/articles/flutter/architecture/dio-cancel-token-lifecycle/)のように別に決めます。

検証は5件です。三つのbranchの詳細履歴とカウンター、スクロール位置、再選択、初期URLからの遷移と`pop`、ルーター再生成後の初期化を確認しました。実機の戻るジェスチャー、ブラウザ履歴、プロセス終了後の復元、メモリ使用量の測定は未検証です。
