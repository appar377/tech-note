`final`を付けたListには、あとから要素を追加できます。変数への再代入を止めることと、そこから参照するオブジェクトを変更できなくすることは、別の制約だからです。

まず、この二つを比べると違いが見えます。以下のDart標準ライブラリの例は、Dart SDK 3.11.5で確認しています。

## finalなListの中身は変更できる

```dart
void main() {
  final colors = <String>['teal'];
  colors.add('ivory');
  print(colors); // [teal, ivory]

  // colors = ['blue']; // 再代入はできない
}
```

`final`が制限するのは、変数`colors`への代入です。このList自体は変更可能なので、`add`は成功します。フィールドをすべて`final`にしたクラスでも、そのフィールドが変更可能なListを指していれば、Listの要素まで固定されるわけではありません。[Dartの変数の説明](https://dart.dev/language/variables)でも、finalとオブジェクトの不変性は区別されています。

値が実行時に決まることも問題ありません。`final now = DateTime.now();`は書けますが、`const now = DateTime.now();`はコンパイル時定数にならず、解析エラーになります。

## constなListは変更できない

```dart
void main() {
  const colors = <String>['teal'];
  try {
    colors.add('ivory');
  } on UnsupportedError {
    print('変更できない');
  }
}
```

こちらは`UnsupportedError`を捕捉します。`const`のコレクションは変更できません。`const`変数にはコンパイル時に評価できる定数式が必要で、変数への再代入もできません。

混同しやすいのは`final colors = const <String>['teal'];`です。この場合もListは変更できません。変数の宣言が`final`でも、右辺で作ったオブジェクトがconstだからです。

| 確かめたいこと | final | const |
| --- | --- | --- |
| 変数へ再代入できるか | できない | できない |
| 初期値が実行時に決まってよいか | よい | コンパイル時定数が必要 |
| 参照先のListの変更を禁止するか | finalだけでは禁止しない | constのListは変更できない |

## const constructorを持つクラスでも、呼び方で変わる

```dart
class Palette {
  const Palette(this.name);
  final String name;
}

void main() {
  const first = Palette('teal');
  const second = Palette('teal');
  final runtime = Palette('teal');

  print(identical(first, second)); // true
  print(identical(first, runtime)); // false
}
```

最初の二つはconstの文脈で生成した同じ定数なので、同一のインスタンスになります。これが定数のcanonicalizationです。最後の呼び出しにはconstの文脈がなく、通常のインスタンスを作っています。const constructorを宣言しただけで、すべての呼び出しが定数になるわけではありません。[コンストラクタの説明](https://dart.dev/language/constructors)と[identicalのAPI](https://api.dart.dev/dart-core/identical.html)で、この違いを確認できます。

const constructorを持つクラスではインスタンスフィールドを`final`にする必要があります。そのうえで、constとして呼び出すときは引数なども定数式でなければなりません。

## late finalは「あとで一度だけ代入する」

```dart
class DeferredLabel {
  late final String value;
}

void main() {
  final label = DeferredLabel();
  label.value = 'ready';
  print(label.value); // ready

  // もう一度 label.value に代入すると、実行時エラーになる。
}
```

`late final`は再代入を許すためのものではありません。このフィールドへの二度目の代入は実行時に失敗します。一方、ローカル変数で二度目の代入が明らかなコードは、解析段階で検出されることがあります。初期化前に読む場合も問題になるため、初期化の順序を呼び出し側に任せてよいかを考える必要があります。

また、`late final value = compute();`のように初期化式を付けた場合は、初回の読み出しまで評価を遅らせます。「あとで代入する」と「初期化式を遅延評価する」は、書き方と利用目的を分けて読むと理解しやすくなります。[lateの説明](https://dart.dev/language/variables#late-variables)

## Flutterでは、定数にできる範囲で使う

Flutterの公式ガイドは、可能な箇所でconst constructorを使うことを勧めています。ただし、const Widgetにすればすべての再ビルドがなくなる、という意味ではありません。ここではアプリの性能計測はしていないので、改善率も示せません。[Flutterの性能ガイド](https://docs.flutter.dev/perf/best-practices)

値が実行時に決まるなら`final`、式全体を定数にできるなら`const`。さらに変更可能なコレクションを持つなら、その中身を変更してよい設計かも別に確認します。これで、変数の固定とオブジェクトの不変性を同じ意味で扱わずに済みます。
