MT5のウィンドウが表示できたら、その条件で画面を描画できたことは確認できます。ただし、Pythonから接続できることや、ログインセッションを離れても同じように動くことまでは分かりません。

この記事では、GUIの観測を次の切り分けに使える形で残す方法を考えます。Lubuntu・Xubuntu・Kubuntuなどの候補選びは[OS選定](/tech-note/articles/linux/mt5-ubuntu/01-os-selection/)で扱い、ここでは同じ確認項目を使います。以下は確認計画と説明用コードであり、MT5を実際に起動・操作した結果ではありません。

## 画面を確かめる前に、どの条件を固定しますか

比較の単位を「UbuntuかLubuntuか」だけにすると、Wineや表示方法の違いまでOSの違いに見えてしまいます。少なくとも次の条件を区別して記録します。

| 記録する条件 | 区別したい差分 |
|---|---|
| OSの版とアーキテクチャ | 同じflavorでも、別リリースや別アーキテクチャを比較していないか |
| デスクトップとセッションの種類 | デスクトップの名前とX11・Waylandを混ぜていないか |
| Wineの版と設定 | Wineの更新や表示ドライバーの違いが含まれていないか |
| 対象のMT5とWine prefix | 同じ実行ファイル・設定の組み合わせを見ているか |
| 解像度、拡大率、表示の確認方法 | ローカル表示と遠隔表示など、観測条件が違っていないか |
| 起動のしかた | 対話的なセッションからの起動か、サービスからの起動か |

prefixや実行ファイルの詳しい整理は[WineとMT5の導入](/tech-note/articles/linux/mt5-ubuntu/04-wine-mt5-installation/)へ分けます。比較記録では、説明用の識別子を使い、環境全体の一覧や個人のホームディレクトリをそのまま貼る必要はありません。

## 環境変数から表示経路を断定できますか

`XDG_SESSION_TYPE`はセッションの種類を示す情報です。個々のプロセスがどの表示ドライバーを使い、接続に成功したかを報告する値ではありません。[pam_systemdの環境変数](https://github.com/systemd/systemd/blob/v255/man/pam_systemd.xml)

次の`session-hints.sh`は、セッションの種類と表示関連の環境変数に空でない値があるかを表示します。Bashの組み込み機能だけを使い、パスの値そのものは表示せず、表示サーバーや認証ファイルにも接続しません。

```bash file=session-hints.sh
#!/usr/bin/env bash
set -eu

case "${XDG_SESSION_TYPE-}" in
  x11|wayland|tty) session_kind="$XDG_SESSION_TYPE" ;;
  '') session_kind=unset ;;
  *) session_kind=other ;;
esac

presence() {
  if [ -n "$1" ]; then
    printf '%s' nonempty
  else
    printf '%s' empty-or-unset
  fi
}

printf 'session_kind=%s\n' "$session_kind"
printf 'DISPLAY=%s\n' "$(presence "${DISPLAY-}")"
printf 'WAYLAND_DISPLAY=%s\n' "$(presence "${WAYLAND_DISPLAY-}")"
printf 'XAUTHORITY=%s\n' "$(presence "${XAUTHORITY-}")"
```

`nonempty`は文字列が空でないこと、`empty-or-unset`は空か未設定であることを意味します。ファイルの存在、認証情報の正しさ、サーバーへの到達性は検査していません。

説明用に`XDG_SESSION_TYPE=wayland`、`DISPLAY=:87`、`WAYLAND_DISPLAY=synthetic-wayland`を与え、`XAUTHORITY`を未設定にすると、期待する出力は次です。この値は実環境から採取したものではありません。Bash 3.2.57でこの例を含む5つの合成入力を確認し、未設定・X11・Wayland・未知のセッション名について出力が期待値と一致しました。

```text
session_kind=wayland
DISPLAY=nonempty
WAYLAND_DISPLAY=nonempty
XAUTHORITY=empty-or-unset
```

ここから「WineがWaylandへ接続した」とは結論できません。Waylandセッションの中でも、X11アプリはXwaylandを通じて表示できます。[WaylandのX11アプリ対応](https://wayland.freedesktop.org/docs/book/Xwayland.html)

また、Wine 10.0の仕様ではX11とWaylandの両方が利用できるときにX11ドライバーが優先されます。この版付きの説明からも、セッション名だけでアプリの経路を決められないことが分かります。[Wine 10.0のリリースノート](https://github.com/wine-mirror/wine/blob/wine-10.0/ANNOUNCE.md)

X11認証についても、`XAUTHORITY`が空でないことだけで認証成功とは判断できません。未設定時の扱いも含め、[Wayland・X11・Xauthorityの整理](/tech-note/articles/linux/mt5-ubuntu/03-wayland-x11-xauthority/)で接続と認証を分けます。

## GUIで観測できる範囲はどこまでですか

次の表は結果の報告ではなく、観測項目と判断の範囲を対応させたものです。まだ試していない項目には「未確認」と残します。

| 観測項目 | 確認すること | その結果に含めないこと |
|---|---|---|
| ウィンドウの表示 | 表示されるか、描画が欠けないか、サイズを変えられるか | API接続や継続稼働 |
| 文字の表示 | メニューやダイアログの文字が読めるか | 別の解像度・拡大率・言語での表示 |
| 入力とフォーカス | メニューの選択、ウィンドウ間のフォーカスが扱えるか | 無人での起動や復旧 |
| 起動時のダイアログ | 何が表示され、処理がそこで止まっていないか | 追加処理を自動化できること |
| 終了操作 | 対象のウィンドウを通常の操作で閉じられるか | すべての関連プロセスの終了 |

MetaQuotesの導入手順にはWineのMonoやGeckoの確認ダイアログも登場します。ただし、毎回すべての環境で同じダイアログが出るという意味ではありません。表示された場合は、どの段階で何が必要になったかを記録します。[MetaTrader 5のLinux導入ガイド](https://www.metatrader5.com/en/terminal/help/start_advanced/install_linux)

## 表示できた結果を、別の構成へどう引き継ぎますか

引き継ぐのは、確認した条件と、その条件で観測した結果です。たとえば「同じWineの版・prefixで、ある対話セッションからウィンドウを表示できた」という記録なら、サービスからの起動へ変えた時点で、起動主体やセッションへの接続が再確認の対象になります。

そこで表示されなくなっても、原因を直ちに`DISPLAY`だけへ決めません。表示経路、実行ユーザー、prefix、対象の実行ファイルなど、変更された条件を一つずつ確認します。環境変数の有無を出すコードは、その比較の一部に使えますが、原因を自動判定するものではありません。

Python連携はterminalとのプロセス間通信を使うため、GUI表示とは別の確認です。[Python Integration](https://www.mql5.com/en/docs/python_metatrader5)

接続条件は[Python連携の記事](/tech-note/articles/linux/mt5-ubuntu/05-mt5-python-api-integration/)へ、対話セッションから離れた起動は[headless設計](/tech-note/articles/linux/mt5-ubuntu/03-ubuntu-server-headless-design/)と[systemdでの管理](/tech-note/articles/linux/mt5-ubuntu/06-systemd-operation/)へ進みます。
