Wine経由でMT5を導入するときは、インストーラーの完了だけでなく、後から同じ環境を起動できる記録が必要です。まず、**どのユーザーが、どのprefixを使い、どの実行ファイルを起動するか**を決めます。

MetaTrader 5公式はLinux上でWineを使う方法を案内しています。本稿はその手順の範囲と、導入前後に分けて確認する項目を整理します。WineやMT5のインストール、起動、口座接続は実行していません。[MetaTrader 5: Installation on Linux](https://www.metatrader5.com/en/terminal/help/start_advanced/install_linux)

## 公式のLinux導入スクリプトは何を行うのか

2026年10月2日に参照した公式ページでは、Ubuntu、Debian、Linux Mint、Fedoraを判定し、Wineのパッケージを導入してからMT5のインストーラーを起動するスクリプトが案内されています。単一のアプリ用ファイルを置くだけの処理ではなく、OS側のパッケージ変更も含む説明です。

公式ページは管理者権限のないターミナルから開始し、導入の途中で必要な権限を与える流れを説明しています。OSパッケージを導入する権限と、Wine上のアプリを動かすユーザーは分けて考えます。[MetaTrader 5: Installation on Linux](https://www.metatrader5.com/en/terminal/help/start_advanced/install_linux)

ここでは配布スクリプトを取得・監査・実行していないため、コマンド一行をコピーして即実行する手順にはしません。実際に導入する段階では、公式リンクの配布物、対象OSとCPU構成、変更するパッケージ、生成先、更新方法を確認する必要があります。資料で案内されるOS名と、個別の版・構成での動作確認は同じではありません。

OSやCPU構成の判断は[実行環境の選定](/tech-note/articles/linux/mt5-ubuntu/01-os-selection)、表示先を用意する条件は[headless構成](/tech-note/articles/linux/mt5-ubuntu/03-ubuntu-server-headless-design)へ分けます。

## prefixは実行ファイルのフォルダなのか

`WINEPREFIX`はWineが状態を保存するディレクトリを指定します。Wine 10.0のman pageでは、未指定時の既定値は`$HOME/.wine`です。レジストリや設定などの状態に関わるため、同じ実行ファイルを指定してもprefixが違えば同じ状態を参照するとは限りません。[Wine 10.0: WINEPREFIX](https://github.com/wine-mirror/wine/blob/wine-10.0/loader/wine.man.in)

一方、`terminal64.exe`のパスは起動対象です。Linux側のファイルパス、Wine内のドライブ表現、アプリのデータ保存先を一つの値として扱わないようにします。Wineのドライブ対応はprefix内の`dosdevices`で表現されますが、prefixを指定するだけでLinuxのファイル権限や隔離境界が作られるわけではありません。[Wine 10.0: Files / Program Arguments](https://github.com/wine-mirror/wine/blob/wine-10.0/loader/wine.man.in)

MT5にも実行ファイルの場所とデータフォルダーの区別があります。導入方式や起動条件を確認せず、すべてのデータが実行ファイルの隣にあるとは決めません。[MetaTrader 5: Files and Folders](https://www.metatrader5.com/en/terminal/help/start_advanced/structure)

公式Linuxページには`.mt5`以下の既定パスが記載されていますが、独自に指定したprefixの例と混ぜないようにします。次の表は公式スクリプトの実測結果ではなく、記録項目を示す合成例です。

| 項目 | 説明用の値 | 何を区別するか |
| --- | --- | --- |
| 実行ユーザー | `wine-demo` | Linux上でファイルへアクセスする主体 |
| prefix | `/srv/wine-demo/prefix` | Wineの状態を保存する場所 |
| 実行ファイル | prefix内の`Example Terminal/terminal64.exe` | 今回起動するアプリ |
| 実行時の表示経路 | 別途X11かWaylandかを記録 | prefixからは決まらない表示先 |

## 導入時と起動時の取り違えをどう見つけるか

次のRuby 3.4向けコードは、記録したユーザー・prefix・実行ファイルと、起動予定の値を比較します。合成値だけを扱い、OSのユーザー、環境変数、ファイル、Wine、MT5は読み取りません。

```ruby file=cli-workbench/launch_contract.rb
# frozen_string_literal: true

require "json"

def differing_launch_fields(expected, actual)
  %i[run_user wine_prefix terminal_path].filter_map do |field|
    field.to_s unless expected.fetch(field) == actual[field]
  end
end

# 説明用の合成値です。OS、環境変数、実ファイルを読みません。
recorded = {
  run_user: "wine-demo",
  wine_prefix: "/srv/wine-demo/prefix",
  terminal_path: "/srv/wine-demo/prefix/drive_c/Program Files/Example Terminal/terminal64.exe"
}

launches = {
  same: recorded.dup,
  different_user: recorded.merge(run_user: "another-user"),
  different_prefix: recorded.merge(wine_prefix: "/srv/wine-demo/another-prefix"),
  different_terminal: recorded.merge(terminal_path: "/srv/wine-demo/other/terminal64.exe"),
  omitted_prefix: recorded.reject { |key, _| key == :wine_prefix },
  empty_prefix: recorded.merge(wine_prefix: "")
}

puts JSON.generate(launches.transform_values { |launch| differing_launch_fields(recorded, launch) })
```

期待値は、`same`だけが空配列です。ユーザー、prefix、実行ファイルを変えたケースでは対応するフィールド名が返ります。prefixを省略した場合と空文字の場合も、明示した記録と一致しないため`wine_prefix`が返ります。

これは「この運用では記録値を明示して揃える」という方針の比較です。Wine一般の有効・無効を判定するものではありません。空配列でも、パスの存在、所有者、アクセス権、ドライブ対応、アプリの起動成功は確認できません。文字列が同じでも、別のWine実行ファイルや更新後の状態を使っていないかは別の記録で確かめます。

Ruby 3.4.4でこのCLI例を実行し、6ケースのJSONが上の期待値と一致することを確認しました。本文から取り出した同じコードでも一致しています。合成記録の文字列比較であり、Linuxへの導入成功を示すログではありません。

## 導入後の何を、次の工程へ渡すか

引き継ぐ記録を、設定値と観測結果に分けます。

| 記録 | 内容 |
| --- | --- |
| 導入条件 | OSの版、CPU構成、Wineの版と入手元、MT5の配布元・版 |
| 起動条件 | 実行ユーザー、prefix、実行ファイル、表示経路 |
| 表示の確認 | ウィンドウが開いたか、必要な表示や操作ができたか |
| 状態の保存先 | 実行ファイルとデータの場所を区別した記録 |
| 未確認 | API接続、再起動後の復旧、長時間の動作など |

Wineの版を表示する`wine --version`も含め、本稿ではLinux固有の確認コマンドを実行していません。prefix全体や生のログを公開用の記録として扱わず、必要な構成情報だけを分けます。アプリの保存状態を含む可能性があるためです。

ウィンドウが開いたことから、Python連携や再起動後の復旧まで成功したとは結論づけません。[Python API連携の境界](/tech-note/articles/linux/mt5-ubuntu/05-mt5-python-api-integration)と[systemd管理](/tech-note/articles/linux/mt5-ubuntu/06-systemd-operation)は、それぞれの入力と成功条件を持つ次の工程です。
