MT5の画面が表示できても、LinuxのPythonからそのまま接続できるとは限りません。先に「どのPythonでパッケージを読み込むか」と「どのterminalへ接続するか」を分けます。

MetaTrader5のPython連携は、terminalとのプロセス間通信を使います。通常のHTTPクライアントのように、接続先URLだけを指定してOSの差を吸収する仕組みとは異なります。[Python Integration](https://www.mql5.com/en/docs/python_metatrader5)

以下は公式資料と配布ファイルに基づく整理です。Wine上のWindows Python、MT5への接続、口座へのログインは実行していません。

## LinuxのPythonに、同じパッケージを入れれば使えますか

まず、Pythonの版だけでなく、OS・実装・ABI・アーキテクチャを配布物と照合します。確認例としてMetaTrader5 5.0.6231には、次のwheelがあります。

`metatrader5-5.0.6231-cp312-cp312-win_amd64.whl`

この版の公開ファイル一覧はWindows x86-64向けのwheelで構成され、Linux向けwheelは掲載されていません。これは5.0.6231の配布状態の確認であり、将来の版まで同じだという主張ではありません。[5.0.6231の配布ファイル](https://pypi.org/project/metatrader5/5.0.6231/#files)

| ファイル名の部分 | この例で表す条件 |
|---|---|
| 最初の`cp312` | CPython 3.12 |
| 次の`cp312` | CPython 3.12のABI |
| `win_amd64` | Windows x86-64 |

wheelにはPython・ABI・platformの互換性タグがあります。「Python 3.12を使っている」という一致だけでは、Windows向けwheelとLinuxのPythonが適合することにはなりません。[Python Packagingの互換性タグ仕様](https://packaging.python.org/en/latest/specifications/platform-compatibility-tags/)

MetaQuotesのPython連携ガイドもWindows向けPythonを使う例を載せています。ただし、そこにある古いPythonの版を、現在選ぶべき版だとは読みません。採用するMetaTrader5の版について、実際の配布ファイルを確認します。[公式のPython連携手順](https://www.mql5.com/en/docs/python_metatrader5)

## WineでWindows Pythonを動かせば、公式対応と考えてよいですか

MetaQuotesは、LinuxへのMT5導入についてWineを利用する手順を案内しています。一方、その案内はWine上のWindows PythonとMetaTrader5パッケージを組み合わせた接続結果まで示すものではありません。[Linuxへの導入ガイド](https://www.metatrader5.com/en/terminal/help/start_advanced/install_linux)

この2つを分けると、構成ごとの追加確認が見えてきます。

| 構成 | 資料から判断できる範囲と、残る確認 |
|---|---|
| Windows上のPythonとterminal | 公式Python連携手順の構成です。選んだ版・配布物・接続先の適合は別途確認します |
| Wine上のWindows Pythonとterminal | Windows向け配布物を使う構成案です。Wineの版、CPU、prefix、terminalとの通信は、この組み合わせでの確認が必要です |
| Linux Pythonから別プロセスへ中継 | 中継部分を別に設計する構成です。公式パッケージのインストールだけで、その通信路が提供されるわけではありません |

中継を追加すると、要求のタイムアウトや接続断、応答を受け取れなかった場合の扱いも設計対象になります。この記事では中継プログラムを実装していません。

Wine prefixは、Wineが扱う設定やファイルのまとまりです。Pythonとterminalについて同じprefixを意図したとしても、それだけを通信成功の証拠にはできません。prefixと実行ファイルの対応は、[WineとMT5の導入](/tech-note/articles/linux/mt5-ubuntu/04-wine-mt5-installation/)で整理しています。

## initializeは、何を開始する関数ですか

`initialize()`はterminalへの接続を確立し、必要であればterminalも起動します。実行ファイルを指定する場合、公式仕様の`path`は先頭の無名引数です。呼び出しの形は`initialize(terminal_path)`であり、`path=`というキーワード引数として説明しません。[initializeの引数と動作](https://www.mql5.com/en/docs/python_metatrader5/mt5initialize_py)

引数を省略するとterminalの自動探索が行われます。また、接続情報を省略した場合には、直前の口座やterminalに保存された情報が使われることがあります。このため、`initialize()`を「設定も接続状態も変えない診断」として無条件に実行することはできません。同じ公式ページで、省略時の動作も確認します。

関数の責務は次のように分かれます。これはAPIの説明であり、実行順を並べた接続スクリプトではありません。

| 関数 | 公式仕様で扱う対象 |
|---|---|
| `initialize()` | terminalへの接続。必要に応じてterminalを起動 |
| `login()` | 指定した口座への接続 |
| `shutdown()` | 確立したPython連携の接続を閉じる |

`login()`はterminalの起動確認とは別の操作です。また、`shutdown()`の説明は接続を閉じることであり、terminalプロセスの終了を保証するAPIとしては扱いません。[login](https://www.mql5.com/en/docs/python_metatrader5/mt5login_py)、[shutdown](https://www.mql5.com/en/docs/python_metatrader5/mt5shutdown_py)

## 接続できないとき、どの境界から調べますか

「APIが使えない」を一つの原因へ決めず、失敗が分かった段階を切り出します。

| 分かったこと | 次に照合する条件 | まだ結論できないこと |
|---|---|---|
| 適合する配布物が見つからない | パッケージの版、Pythonタグ、ABI、platform | terminalや表示先の異常 |
| パッケージの読み込みに失敗した | 実行したPythonと、その環境に入れた配布物 | terminalへの接続可否 |
| `initialize()`が失敗した | 接続先の選択、起動条件、関数の結果とエラー | 単一の原因や表示経路の故障 |
| 接続できたが後続関数が失敗した | 失敗した関数の契約と、その時点の状態 | すべてを初期接続の問題として扱うこと |

`last_error()`はPythonライブラリの直近のエラーコードと説明を返し、独自のコード体系を使います。たとえばIPCのタイムアウトという結果だけでは、prefix、表示先、対象プロセスのどれが原因かまでは確定しません。結果を残す場合は、失敗した関数と結び付けます。[last_errorの仕様とコード一覧](https://www.mql5.com/en/docs/python_metatrader5/mt5lasterror_py)

記録には、説明用の接続先ID、選んだ版、呼び出した関数、結果、発生時点があれば切り分けの入口になります。口座情報全体や保存済みの接続情報を、そのまま記事や共有ログに貼る必要はありません。

## サービス化の前に、何を決めておきますか

terminalを独立したサービスが起動するのか、Python側の接続処理による起動を許すのかを先に決めます。両方が無条件に起動・再起動すると、どちらが対象プロセスを管理するのかが曖昧になります。

そのうえで、実行ユーザー、Wine prefix、Windows側から見た実行ファイル、Pythonの環境、選んだ表示経路を一組として記録します。GUI表示だけを確認した構成に、API接続済みという印を付けないことも必要です。

起動の担当と接続確認をサービスへ落とし込む話は、[systemdでの管理](/tech-note/articles/linux/mt5-ubuntu/06-systemd-operation/)へ進みます。接続成功を確認したとしても、それはその条件での接続結果であり、継続稼働や後続処理の成功まで含みません。
