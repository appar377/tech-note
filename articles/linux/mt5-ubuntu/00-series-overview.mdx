MT5をUbuntu系Linuxで扱うときは、OSを選ぶことと、画面を表示すること、Pythonから接続することを分けて考えると、次に確かめる対象が明確になります。

MetaQuotesはLinuxへの導入方法としてWineを使う手順を案内しています。ただし、その手順の存在だけで、任意のデスクトップ、CPUアーキテクチャ、Python環境、常駐方法の組み合わせまで動作が保証されるわけではありません。[MetaTrader 5のLinux導入ガイド](https://www.metatrader5.com/en/terminal/help/start_advanced/install_linux)

このシリーズは実行環境の構成と確認方法を扱います。以下は公開資料を基にした設計の整理であり、特定の環境での導入・GUI操作・API接続・連続稼働の実証報告ではありません。

## 最初に分けておくのは、どの層ですか

「Ubuntuで動く」という言葉には、複数の条件が含まれます。確認する対象を次のように分けます。

| 層 | 決めること・記録すること | それだけでは分からないこと |
|---|---|---|
| OSとアーキテクチャ | Ubuntuのリリース、パッケージのアーキテクチャ | Windows向けバイナリとの互換性 |
| デスクトップ | GNOME、LXQt、Xfce、Plasmaなど、人が操作する環境 | 個々のアプリが使う表示経路 |
| 表示経路 | X11、Xwayland、WineのWayland対応など | WineやMT5がその経路へ接続できるか |
| WineとMT5 | Wineの版、prefix、対象の実行ファイル、実行ユーザー | Pythonとの接続や再起動後の復元 |
| Python連携 | PythonのOS・版・アーキテクチャと配布物、接続するterminal | サービスとしての起動順序や復旧 |
| 常駐管理 | 起動するプロセス、環境、終了・再起動の扱い | アプリ側の正常性や継続稼働 |

これは確認対象の分割です。すべての環境が同じ一本の起動順序になる、という意味ではありません。たとえばX11で使う認証情報を、Waylandのすべての構成に共通する必須条件として扱うことはできません。

## デスクトップがWaylandなら、WineもWaylandですか

デスクトップの種類やセッション名だけでは決まりません。Wayland上では、XwaylandというXサーバーを通じてX11アプリを表示できます。アプリからはX11への接続でも、その先はWayland compositorにつながる構成です。[WaylandのX11アプリ対応](https://wayland.freedesktop.org/docs/book/Xwayland.html)

Wineにも版による違いがあります。Wine 10.0のリリースノートではWaylandドライバーが既定で有効になり、両方を利用できる場合にはX11ドライバーが優先されると説明されています。これはWine 10.0の仕様例であり、MT5との組み合わせを検証した結果ではありません。[Wine 10.0のリリースノート](https://github.com/wine-mirror/wine/blob/wine-10.0/ANNOUNCE.md)

そのため「GUIあり」「Waylandセッション」「X11を利用するWine」を別々に記録します。具体的な接続と認証は、[Wayland・X11・Xauthorityの整理](/tech-note/articles/linux/mt5-ubuntu/03-wayland-x11-xauthority/)へ進んでください。

## Ubuntuの情報は、どこまで確認できますか

まずOSのリリースを、対象のLinuxにある`/etc/os-release`から読み取れます。`ID`と`VERSION_ID`はOSと版の識別に使われます。`VERSION_ID`や`VARIANT_ID`は省略されることもあるため、項目がないだけで異常と判断しません。[os-releaseの仕様](https://github.com/systemd/systemd/blob/v255/man/os-release.xml)

次のコードを`read-release.sh`として保存します。引数で指定したファイルから3項目の行を表示するだけで、内容をシェルとして評価しません。引数を省略すると終了し、ホストのファイルを自動では選びません。

```bash file=read-release.sh
#!/usr/bin/env bash
set -eu

if [ "$#" -ne 1 ]; then
  printf '%s\n' 'usage: read-release.sh PATH_TO_OS_RELEASE' >&2
  exit 2
fi

sed -n -e '/^ID=/p' -e '/^VERSION_ID=/p' -e '/^VARIANT_ID=/p' < "$1"
```

読者が対象のUbuntuで確認するときの呼び出しは`bash read-release.sh /etc/os-release`です。こちらでは実環境に対する実行は行っていません。合成のos-releaseファイル2種類と引数省略を使い、行の選択結果と引数がない場合の終了をBash 3.2.57で確認しました。実機のOS情報は取得していません。

たとえば、説明用ファイルに`ID=ubuntu`と`VERSION_ID="24.04"`があれば、期待する表示は次です。

```text
ID=ubuntu
VERSION_ID="24.04"
```

この表示から、利用中のデスクトップ、Wineの版、Pythonの互換性は判断できません。また、仮想マシンやコンテナーの中で読む場合は、その環境のOS情報を見ていることにも注意します。

## Pythonが入っていれば、MT5へ接続できますか

MetaTrader5パッケージは、terminalとのプロセス間通信を使う連携機能です。通常のHTTPクライアントをLinuxに置く話と同じには扱えません。[Python Integration](https://www.mql5.com/en/docs/python_metatrader5)

確認した配布物の例では、MetaTrader5 5.0.6231にWindows x86-64向けのwheelがあります。LinuxのPythonとWindows向けのPythonでは配布物の適合条件が異なるため、OSを決めた後にPythonの実行場所・版・アーキテクチャも確認します。[5.0.6231の配布ファイル](https://pypi.org/project/metatrader5/5.0.6231/#files)

また、公式APIの`initialize()`は必要に応じてterminalを起動する場合があります。「必ず先に人が画面から起動する」という固定手順でもありません。接続先と起動の条件は、[Python連携の記事](/tech-note/articles/linux/mt5-ubuntu/05-mt5-python-api-integration/)で扱います。[initializeの仕様](https://www.mql5.com/en/docs/python_metatrader5/mt5initialize_py)
