Tech Noteでは、一つの疑問に答える記事、短い検討を残すノート、章立てで読むブック、既存記事をたどるシリーズを分けています。同じテーマを扱っていても、読み始める目的と、次の読み物への進み方が異なるためです。

このノートでは、現在のコンテンツ定義と画面の構成をもとに、その役割を整理します。

## 読む目的に合わせて何を選ぶか

| 読みたいもの | 役割 | 入口 |
|---|---|---|
| 一つの技術的な疑問を解く | 記事。前提と具体例を含め、単体でも読める説明にする | [記事一覧](/tech-note/articles/) |
| 一つの気づきや設計上の判断を読む | ノート。検討の範囲と、まだ決めていない点を短く残す | [ノート一覧](/tech-note/notes/) |
| テーマを順序立てて学ぶ | ブック。独立した本文を持ち、章の順序に沿って説明する | [ブック一覧](/tech-note/books/) |
| 共通テーマの記事をたどる | シリーズ。収録記事への目次と、読む目的を示す | [シリーズ一覧](/tech-note/series/) |

ノートから記事へ書き直すことはできますが、すべての文章が「ノート、記事、ブック」の順に移るわけではありません。短い設計判断はノートとして残せますし、一つの問いに答え切れるなら記事として完結できます。

ブックを作るときも、記事を並べただけで章ができるわけではありません。章ごとの前提をつなぎ、説明が重なる部分を整理して、ブック側の本文を作ります。

## 検索と関連記事はどうつながるか

ホームには検索、最近の記事、ブックへの入口、分野とシリーズへのリンクがあります。内容の種類をまだ決めていないときは、キーワードから探し始められます。

[検索ページ](/tech-note/search/)は、記事・ブック・ノートを対象に、タイトルや説明だけでなく本文も検索します。種類と分野で絞り込むこともできます。シリーズの紹介ページ自体は独立した検索対象ではなく、収録記事やシリーズ一覧からたどる構成です。

記事を読み終えた後には、別の疑問へ進むための導線があります。「あわせて読む」はカテゴリ、タグ、定義されたシリーズの一致から候補を選びます。前後の記事は、複数記事のある公開シリーズ内、または同じ記事フォルダ内から選びます。単純にサイト全体の日付順で前後へ進むものではありません。

記事に対応するシリーズやブックがあれば、その入口へのリンクも表示します。ノートは同じ本文・目次の表示を使いますが、現在は記事と同じ自動関連記事欄を持ちません。必要なつながりは本文のリンクで補います。

## ブックとシリーズの目次は何を参照するか

ブックは`books/`のMDXに本文を持ちます。本文の第2階層の見出しを章として扱い、同じページ内で前後の章へ移動できます。参考となる記事は末尾の「関連する記事・資料」へつなぎ、記事の本文を自動で連結することはありません。

シリーズは、`lib/series-books.ts`にある説明と記事の指定から作ります。そこに定義されたシリーズについて、収録対象の公開記事を集めて目次にします。記事のメタデータにシリーズ名を書くだけで、すべての名前が新しいシリーズ一覧として公開される仕組みではありません。

たとえば[世界の拡張子](/tech-note/series/world-file-extensions/)には、現在[MDXの記事](/tech-note/articles/file-formats/extensions/mdx/)が1本あります。入口には、その記事で読める内容と到達点を示す必要があります。未収録の形式まで説明が揃っているように扱うと、目次を開いた読者の期待と食い違います。

なお、ブックはこのサイトが持つ長編コンテンツです。読んだ本を記録する[読書メモ](/tech-note/reading/)は別のページで、現在のデータ定義には公開記録がありません。ブックを増やしても、読書記録が自動で増えるわけではありません。

## ノートの整理状態と公開状態は同じか

ノートのメタデータは、本文が何を扱い、どの段階の文章かを示します。

| 項目 | 現在の役割 |
|---|---|
| `title`と`description` | 一覧や検索から、読む内容を判断するための題名と説明 |
| `area` | ノートの分野。記事の`category`とは別の項目 |
| `tags` | 内容に関する手がかり。検索対象にも含まれる |
| `status` | `rough`または`refined`。ノートの整理状態 |
| `source` | `ai-dialogue`、`manual`、`reading`、`learning`のいずれか。素材の由来を区別する項目 |
| `draft` | そのノートを公開対象から外すかどうか |

`rough`は非公開の指定ではありません。このノートも整理状態は`rough`、公開対象の指定は`draft: false`です。途中の検討を公開するときは、本文の中で分かった範囲を説明する必要があります。

`source`も記事の品質や事実確認を保証する値ではありません。素材の由来を記録する項目であり、会話や読書メモを自動で記事へ変換する処理を意味しません。

## 下書きはどこで公開対象から外れるか

記事とノートは`draft: true`を通常の取得処理から外します。ブックでは`status: published`のものを取得し、`status: draft`を外します。この違いが、一覧、詳細ページ、検索に渡す内容へ反映されます。

| 種類 | 公開状態を決める項目 | 他の項目との区別 |
|---|---|---|
| 記事 | `draft` | `articleType`や難度とは別 |
| ノート | `draft` | `rough`か`refined`かとは別 |
| ブック | `status` | `access`とは別。現在の画面は`free`・`premium`による課金や閲覧制限を行わない |
| シリーズ | 収録対象の記事が公開されているか | 公開記事がないシリーズや節は表示対象から外れる |

下書きレビュー画面は、開発モードで専用のプレビュー設定を有効にしたときだけ、下書き記事を読むためのものです。現在はノートやブックの下書きをまとめて読む画面ではありません。通常の静的出力には、この経路で下書き本文を渡しません。

ここで分けているのは、サイトが公開ページへ含める内容です。ソースファイル自体のアクセス権を管理する機能ではありません。また、公開対象の値を付けても、内容の正確さが確認されるわけではありません。読み物の種類、整理状態、公開判断をそれぞれ分けて扱います。
