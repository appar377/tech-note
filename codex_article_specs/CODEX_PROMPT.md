# Codex実行用プロンプト

以下をCodexへ渡し、`ARTICLE_ID`だけ変更して1記事ずつ生成する。

```text
このリポジトリの `codex_article_specs/README.md` と
`codex_article_specs/articles/<ARTICLE_ID>_*.md` を読み、
その仕様に従って日本語の技術記事を1本執筆してください。

要件:
- 出力先は個別仕様の `output_path`
- front matterを付ける
- 一般的な用語解説ではなく、症状 → 誤解 → 観測 → 内部動作 → 修正比較 → テスト → 一般化の順で書く
- 最小再現コードと再発防止テストを含める
- リポジトリのGemfile、pubspec.yaml、Package.swift、lint設定を確認し、利用バージョンに合う構文だけを使う
- 公式仕様またはリポジトリから確認できない事実を断定しない
- 実案件固有名、秘密、会社名、架空の障害件数を作らない
- 生成後に、技術的断定、コードの整合性、リンク、front matter、表記揺れをセルフレビューする
- 既存記事がある場合は上書きせず、差分を提示する
```

## 複数本を順に生成する場合

```text
`codex_article_specs/articles/` のうちARTICLE_ID 01〜05を番号順に処理してください。
各記事は独立したMarkdownへ出力し、1本ごとに以下を実施してください。

1. 個別仕様を読む
2. 関連する実装・設定ファイルを検索する
3. 記事を書く
4. コード例を静的に検証する
5. 仕様の必須構成が揃っているかチェックする
6. 次の記事へ進む

記事間で同じ説明をコピーせず、相互リンクで補完してください。
```

## Codexがリポジトリ内の実装を見つけられない場合

- 実体験として詳細を補完しない。
- 匿名化した最小再現コードとして明示する。
- バージョン依存の箇所は「利用中バージョンで要確認」とする。
- 不足情報を記事末尾のTODOへ残さず、断定範囲を狭めて完成させる。
